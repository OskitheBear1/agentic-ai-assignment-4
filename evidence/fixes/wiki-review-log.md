# Wiki review log

Every note in `vault/wiki/` was generated by local Gemma and then read against
the original PDF in `vault/raw/`. This log records what was wrong, whether the
fix belonged in the harness or in the note, and where the pre-fix state is kept.

Originals in `vault/raw/` were never edited. Where the model was wrong about a
source, the *note* was corrected — never the evidence.

---

## Failures fixed in the harness (so they cannot recur)

### 1. Invalid JSON from the model
**Symptom:** the first ingestion run died on `Expecting property name enclosed in
double quotes`. Gemma 3n had written its tokenizer's U+2581 glyph (`▁▁`) instead
of spaces for indentation, and had misspelled the key `summary` as `summaary`.
**Fix:** switched to Ollama's structured-output support — the note contract is now
a JSON schema passed as `format`, so the runtime constrains decoding instead of
the prompt merely requesting a shape (`wiki_cli/prompts.py:NOTE_SCHEMA`). Kept two
cheap fallbacks in `wikigen.parse_note_json`: U+2581 is normalised to a space, and
a small alias table repairs misspelled keys.
**Evidence:** the failing reply is quoted in the README reflection section.

### 2. A misspelled note title became a filename
**Symptom:** the model titled the Negotiations note `Negotiaions MBA 252 Fall 2026`.
That string became the filename, the H1, and the Obsidian graph label.
**Fix:** `wikigen.validate_title_against_source` — every word of four or more
letters in a title must appear in the source document. A close match is repaired
from the source's own vocabulary; anything else falls back to a filename-derived
title. On the next run the guard reported
`corrected title: 'Negotiaions' -> 'Negotiations'` and renamed the note, updating
every incoming `[[wikilink]]`.
**Pre-fix state:** `evidence/fixes/before/Negotiaions MBA 252 Fall 2026.md`,
`evidence/fixes/before/vault-check-before.txt`.

### 3. Misspelled people's names
**Symptom:** `Alexaandre Mas` (source: Alexandre Mas) became a People note
filename; `Ijheh Ogbechie` (source: Ijeh Ogbechie) and `Amaador` (source: Amador)
appeared inside section bullets where the name check could not see them.
**Fix:** `wikigen.validate_person_name` for the people list, and
`wikigen.repair_proper_nouns` for all generated prose. The prose guard repairs a
capitalised word of 4+ letters only when the source never uses it and a close
match exists in the source.

### 4. The prose guard over-corrected a correct sentence
**Symptom:** the guard rewrote the bullet `No-class dates: None specified.` to
`One specified.` — inverting the meaning of a sentence that was right.
**Fix:** the guard now skips any word found in the local system wordlist
(`/usr/share/dict/words`, ~234k entries, with a built-in fallback set), and
accepts regular plurals whose stem is known — which also stopped it "fixing"
`Wednesdays` to `Wednesday`. Positional exemptions were dropped, since the
dictionary check protects ordinary words better than position did.
**Pre-fix state:** `evidence/fixes/before/Negotiations-MBA-252-prose-guard-overcorrection.md`
(line 64 shows `- No-class dates: One specified.`).

### 5. Notes transcribed a table instead of summarising a course
**Symptom:** the Asset Management note had 22 one-line sections that were just the
reading-schedule table, and **omitted the grading breakdown, the meeting times and
the absence rule** — the three things anyone would actually open the note for.
**Fix:** the ingest contract now fixes the section headings (`Logistics`,
`Grading`, `Attendance and Lateness`, `Assignments and Deadlines`,
`Readings and Materials`, `Schedule Highlights`) and enumerates them in the JSON
schema, so the model cannot invent its own. `Schedule Highlights` is capped at
notable dates, with the full table left to the unchanged original.
**Pre-fix state:** `evidence/fixes/before/Asset Management MBA 233.md`.

### 6. Contact details copied into shared notes
**Symptom:** the ingest instructions say not to copy email addresses. The model
copied them anyway, and mangled one into `olesky@haaas.bberkeley.edu` — a wrong
address that looked real.
**Fix:** `wikigen.redact_contact_details` strips emails and phone numbers from all
generated prose. The unchanged original in `raw/` remains the record for contact
details, so nothing is lost.

### 7. Topic tags under-applied
**Symptom:** the model tagged only 3 of 6 topics on two sources, omitting
`Fall 2026 Schedule` and `Attendance and Absences` for courses that plainly state
meeting times and absence rules.
**Fix:** `wikigen.verify_topics` — the model proposes tags, and the harness adds
any tag for which the source text contains at least two explicit matches. Tags
are therefore evidenced, not guessed.

### 8. Thirteen thin person notes
**Symptom:** every named guest speaker got its own one-line People note. Fifteen
person notes swamped the graph and none was a page worth opening twice.
**Fix:** only instructional staff (instructor, professor, GSI, GSR, assistant)
get a People note; guest speakers are listed inside the relevant course note.
Stale notes are removed on re-ingestion.

### 9. Broken source links from index.md
**Symptom:** `wiki check` reported 4 unresolvable links — `index.md` sits at the
vault root, but it was emitting `../../raw/...`, a path built for notes two levels
down in `wiki/Topics/`.
**Fix:** `wikigen.render_index` now builds the link relative to the vault root.
`wiki check` reports 0 broken links.

### 10. The offline guard aborted an already-offline run
**Symptom:** `scripts/offline-demo.sh` refused to run *with Wi-Fi already off*:
`ABORT: the internet is still reachable (HTTP 000000 from ollama.com)`.
**Cause:** the guard read curl's printed status code with
`code="$(curl ... -w '%{http_code}' || echo 000)"`. On failure curl prints `000`
**and** the `|| echo 000` fallback appended another, so `code` became `000000`,
which is not equal to `000`, so the guard concluded the network was up.
**Fix:** test curl's **exit status** instead of parsing its output —
`reachable() { curl -s -m 6 -o /dev/null "$1"; }` — and use a separate `probe()`
helper for the human-readable transcript lines. The same bug was present in
`scripts/mode-checks.sh` and was fixed there too.
**Worth recording because** it is the failure mode the assignment warns about in
miniature: a check that looks like it is verifying something while actually
verifying nothing. Had the comparison gone the other way, the script would have
happily certified an online run as offline.

## Statements corrected in the note, not the harness

These three are model misreadings of the source, reproducible across runs, and not
reducible to a general rule. They were corrected by hand in
`vault/wiki/Courses/Negotiations MBA 252.md` on 2026-09-29; the pre-review file is
kept at `evidence/fixes/before/Negotiations-MBA-252-before-human-review.md`.

| # | Model wrote | Source actually says | Correction |
|---|---|---|---|
| 1 | "late submission costs 2 points per day" | "missing one costs 2 points" (per missed worksheet; worksheets are never accepted late at all) | changed to "missing one costs 2 points" |
| 2 | "Required Readings: Thompson, L. (2007)…" | Appendix B heading is **"Recommended Reading"** | relabelled Recommended, with a note that weekly Thompson chapters do appear in the schedule table |
| 3 | "No-class date: 10/10–10/17 (shadow negotiation window)" | "Shadow-negotiate window for Week 8: 10/10–10/17" — an exercise window, not a cancelled class | relabelled as the exercise window, stating the syllabus lists no no-class dates |

## One inconsistency in the source itself, preserved deliberately

The Negotiations syllabus contradicts itself on the press team assignment: the
grading table on page 2 shows "(up to 3 bonus)", while Appendix A calls it
"Press team assignment (10 points)". The ingest rules tell the model to record
both figures rather than silently pick one, and the note does. This is a fault in
the source, not in the wiki, so it was left visible.
